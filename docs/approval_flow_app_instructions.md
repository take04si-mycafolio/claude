# 【アプリ側実装指示】ミッション特典の運営承認制＋使用記録の承認制

2026-07-30 導入。sc-tsusho バックエンド側は実装・本番反映済み。アプリ側は以下の2点の表示対応をしてほしい。レスポンスの既存フィールドは削除・変更なし（追加のみ・後方互換）。

## 変更点1: ミッション特典(コード)は運営承認後に発行される

これまでミッション達成と同時にコードが発行されていたが、達成時点では**承認待ち**になり、運営が承認した時点でコードが発行される。承認されるとコードは API に載り、登録メールアドレスにも案内メールが届く。

`GET /api/missions/` の各ミッションに以下が追加/変更:

| フィールド | 型 | 意味 |
|---|---|---|
| `reward_status` | string | `"waiting"`(承認待ち) が新規追加。既存: `"awarded"` / `"pending"`(コード準備中) / `"sold_out"` / `""`(未達成) |
| `waiting_approval` | bool | `reward_status == "waiting"` の糖衣。true なら承認待ち表示 |

### アプリ側の実装
- 達成済みミッションのコード表示部で分岐を追加:
  - `waiting_approval: true` →「🕐 運営が内容を確認しています（承認待ち）。承認されるとコードが表示され、メールでもお知らせします。」
  - `reward_code` 非空 → 従来どおりコード表示。
  - `reward_status: "pending"` → 従来どおり「コード準備中」。
  - `reward_status: "sold_out"` → 従来どおり「定員終了」。
- 達成直後の完了演出で「プレゼント獲得！」のような文言を出している場合は「達成！承認後にプレゼントをお届けします」系に変更する。
- `reward_status` に未知の値が来ても落ちないよう default 分岐を残すこと。

## 変更点2: 使用記録(use-logs)も承認制になった

`POST /api/products/{id}/use-logs/` で投稿した使用記録は承認待ちで作成され、運営承認後に他ユーザーへ公開される。口コミ(reviews)は導入済みの承認制と同じ扱い。

- `GET /api/products/{id}/use-logs/` は「承認済み全件＋自分の承認待ち」を返す（他人の承認待ちは含まれない）。
- 一覧・投稿成功(201)レスポンスの各アイテムに `is_approved`(bool) が追加された。

### アプリ側の実装
- `is_approved: false` の使用記録カードに「🕐 承認待ち」バッジを表示（自分の投稿にしか出ない）。
- 投稿成功時のメッセージを「投稿ありがとうございます。内容を確認のうえ掲載されます。」に変更。
- 投稿直後に一覧へ自分の投稿が現れるのは正常（承認待ちバッジ付き）。他ユーザーには承認後に見える。

## 動作確認チェックリスト
- [ ] ミッション達成直後: 承認待ち表示（コードが出ない）
- [ ] 運営承認後(再取得): コード表示＋メール受信
- [ ] `reward_status: "sold_out"` / `"pending"` の既存表示が壊れていない
- [ ] 使用記録投稿直後: 自分の一覧に承認待ちバッジ付きで表示
- [ ] 別アカウントから同商品の一覧を見ると未承認の投稿が見えない
